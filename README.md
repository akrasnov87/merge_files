# merge_files.py

Утилита на Python 3 для рекурсивной склейки файлов из каталога в один
(или несколько) выходных файлов. Предназначена для подготовки контекста
для ИИ: вместо ручного перетаскивания десятков файлов в окно чата — один
готовый bundle (или несколько, сгруппированных по папкам).

- **Никаких внешних зависимостей** — только стандартная библиотека Python 3.
- Полноценная поддержка `.gitignore`-совместимых правил (свой парсер).
- **Приватные правила `#!#`** — игнорирование файлов без изменения
  поведения git.
- Пропуск бинарных файлов по умолчанию.
- Разбиение результата на части заданного размера.
- Разбиение по папкам верхнего уровня (`--split-by-dir`).
- **Древовидная статистика по подпапкам** в конце работы — видно, какая
  ветка каталогов занимает больше всего места (`--stats`, `--stats-depth`,
  `--stats-min-bytes`).
- Стабильный порядок вывода (детерминированный результат).

Текущая версия: **1.5.0**

## Установка

Скопируйте `merge_files.py` в удобное место. Требуется Python 3.8+.

```bash
python3 --version
```

Опционально — сделайте исполняемым и положите в `PATH`:

```bash
chmod +x merge_files.py
sudo mv merge_files.py /usr/local/bin/merge-files
```

## Быстрый старт

```bash
# Слить всё содержимое ./my_project в один bundle.txt
python3 merge_files.py ./my_project bundle.txt
```

Результат — `bundle.txt`, внутри каждый файл помечен маркерами:

```
===== FILE: src/main.py =====
def hello():
    print("world")
===== END FILE =====

===== FILE: README.md =====
# Project
===== END FILE =====
```

В конце работы печатается **дерево статистики** по подпапкам — сразу
видно, какая ветка занимает больше всего места (см.
[Статистика по подпапкам](#статистика-по-подпапкам)).

## Синтаксис

```
python3 merge_files.py <source> <output> [опции]
```

| Аргумент / опция | Описание |
|---|---|
| `source` | Исходная директория (обязательно) |
| `output` | Выходной файл или префикс при разбиении (обязательно) |
| `--max-size MB` | Максимальный размер одного выходного файла в мегабайтах. `0` (по умолчанию) — без ограничения |
| `--split-by-dir` | Каждая папка верхнего уровня получает свой бандл. В корневой файл попадают только файлы, лежащие прямо в `source` |
| `--stats-depth N` | Максимальная глубина дерева статистики (по умолчанию `3`; `0` — без ограничения). См. [Статистика по подпапкам](#статистика-по-подпапкам) |
| `--stats-min-bytes N` | Не показывать в дереве ветки меньше N байт (по умолчанию `1024`, т.е. 1 КБ) |
| `--stats-all` | Показывать все ветки, включая пустые и мелкие (эквивалент `--stats-min-bytes 0`) |
| `--no-stats` | Не выводить статистику в конце |
| `--ignore FILE` | Файл с правилами игнорирования. По умолчанию `.gitignore` в корне `source` |
| `--no-ignore` | Не читать файл игнорирования |
| `--no-private-ignore` | Не обрабатывать приватные правила `#!#...` — трактовать их как обычные комментарии |
| `--include-binary` | Включать бинарные файлы (по умолчанию пропускаются) |
| `--version` | Показать версию скрипта и выйти |
| `-h`, `--help` | Показать справку |

## Примеры

### Всё в один файл

```bash
python3 merge_files.py ./my_project bundle.txt
```

### Разбить на части по 5 МБ

```bash
python3 merge_files.py ./my_project bundle.txt --max-size 5
```

Будут созданы файлы:

```
bundle_part001.txt
bundle_part002.txt
bundle_part003.txt
...
```

### Разбить по папкам верхнего уровня

```bash
python3 merge_files.py ./my_project bundle.txt --split-by-dir
```

Если в `./my_project` есть:

```
my_project/
├── README.md
├── LICENSE
├── src/
│   └── ...
├── docs/
│   └── ...
└── tests/
    └── ...
```

Будут созданы:

```
bundle.txt          ← только README.md + LICENSE
bundle_src.txt      ← всё содержимое src/
bundle_docs.txt     ← всё содержимое docs/
bundle_tests.txt    ← всё содержимое tests/
```

Это удобно, когда проект большой и хочется передавать в ИИ
логически связанные куски (например, только `src` или только `docs`).

### Комбинация: по папкам и по 2 МБ

```bash
python3 merge_files.py ./my_project bundle.txt --split-by-dir --max-size 2
```

Каждая папка разбивается на свои части независимо:

```
bundle.txt
bundle_src_part001.txt
bundle_src_part002.txt
bundle_docs_part001.txt
bundle_docs_part002.txt
...
```

### Свой файл игнорирования

```bash
python3 merge_files.py ./my_project bundle.txt --ignore .myignore
```

Путь может быть абсолютным или относительным (тогда ищется внутри `source`).

### Отключить `.gitignore`

```bash
python3 merge_files.py ./my_project bundle.txt --no-ignore
```

### Не учитывать приватные правила

```bash
python3 merge_files.py ./my_project bundle.txt --no-private-ignore
```

Строки `#!#...` будут проигнорированы полностью (как обычные `#`-комментарии).

### Включить всё, даже бинарники

```bash
python3 merge_files.py ./my_project bundle.txt --include-binary
```

### Посмотреть версию

```bash
python3 merge_files.py --version
# merge_files 1.5.0
```

### Дерево статистики на большую глубину

```bash
python3 merge_files.py ./my_project bundle.txt --stats-depth 10
```

### Показать вообще все ветки, даже совсем мелкие

```bash
python3 merge_files.py ./my_project bundle.txt --stats-all
```

### Отключить статистику

```bash
python3 merge_files.py ./my_project bundle.txt --no-stats
```

## Файл игнорирования

Используется синтаксис, совместимый с `.gitignore`. Пример `.gitignore`:

```gitignore
# Комментарии

# Служебные каталоги
.git/
.idea/
.vscode/

# Зависимости и сборки
node_modules/
__pycache__/
*.pyc
dist/
build/
target/

# Логи и артефакты
*.log
*.tmp
*.cache

# Медиа (перестраховка — бинарники и так пропускаются)
*.png
*.jpg
*.pdf

# Исключение из исключений
!important.log
```

### Поддерживаемые конструкции

| Синтаксис | Значение |
|---|---|
| `# текст` | комментарий |
| `pattern` | совпадение на любом уровне вложенности |
| `!pattern` | инверсия: «не игнорировать» (последнее правило побеждает) |
| `*` | любые символы, кроме `/` |
| `**` | любые символы, включая `/`; `**/` — ноль или более каталогов |
| `?` | ровно один символ, кроме `/` |
| `[abc]`, `[!abc]` | класс символов |
| `dir/` | только каталог (и его содержимое) |
| `/pattern` | привязан к корню `source` |
| `foo/bar` | автоматически привязан к корню (как в git) |
| `\ ` в конце строки | экранированный пробел |
| `\!`, `\#` | экранирование первого символа |
| `#!#pattern` | **приватное правило** — см. ниже |

### Правила применения

- Правила применяются по порядку.
- Если путь совпал с несколькими правилами — решает **последнее**.
- `!`-правило «отменяет» игнор, если оно идёт после соответствующего
  правила игнорирования.
- Игнорируемые каталоги **не обходятся** — это ускоряет работу на
  больших деревьях (например, `node_modules/`).

## Приватные правила `#!#`

Иногда нужно, чтобы утилита игнорировала файл, но **git о нём не знал**.
Например, не хочется коммитить в общий репозиторий строку вроде
`pear.key` — но при этом не хочется тащить ключ и в bundle для ИИ.

Для этого предусмотрен префикс `#!#`. Для git такие строки — обычный
комментарий (начинаются с `#`), поэтому он их игнорирует. Утилита
разбирает их как полноценные правила.

### Пример

```gitignore
# Обычные правила — видны и git, и утилите
node_modules/
*.pyc
dist/

# Приватные правила — git видит их как комментарий, утилита применяет
#!#pear.key
#!# *.pem
#!# secrets/
#!# config/local.json
#!# !config/local.example.json
```

Эквивалентно применению:

```gitignore
pear.key
*.pem
secrets/
config/local.json
!config/local.example.json
```

но без последствий для git.

### Правила синтаксиса

- Строка должна начинаться с `#!#` **без пробелов впереди**.
- После префикса допускается **один** пробел для читаемости:
  `#!# foo` ≡ `#!#foo`.
- Всё остальное — обычный синтаксис `.gitignore`:
  - `!` — инверсия,
  - `dir/` — каталог,
  - `*`, `**`, `?`, `[...]` — глобы,
  - `/prefix` — привязка к корню,
  - `a/b` — авто-привязка к корню.
- Приватные правила применяются **в общем порядке** с обычными:
  последнее совпавшее решает. То есть можно сделать так:

  ```gitignore
  secrets/
  #!# !secrets/public.txt
  ```

  — каталог `secrets/` игнорируется для git и утилиты, но файл
  `secrets/public.txt` попадает в bundle.

- Пустые приватные правила (`#!#`) игнорируются.
- Строка вида `# #!#foo` (пробел перед `#!#`) — обычный комментарий,
  **не** приватное правило.
- Строка вида ` #!#foo` (пробел в начале) — тоже обычный комментарий
  (по правилам git).

### Статистика при запуске

Утилита показывает, сколько правил каждого типа загружено:

```
Правил из /path/project/.gitignore: 5 обычных, 2 приватных
```

### Отключение

Если по какой-то причине нужно трактовать `#!#` как обычные
комментарии — используйте флаг:

```bash
python3 merge_files.py ./my_project bundle.txt --no-private-ignore
```

В этом случае все строки `#!#...` будут полностью проигнорированы.

### Важное замечание

Приватные правила **не являются секретными в смысле git** — если вы
закоммитите `.gitignore`, они уедут в репозиторий вместе с ним. Если
нужна настоящая приватность (правило только на вашей машине),
используйте отдельный файл:

```bash
python3 merge_files.py ./my_project bundle.txt --ignore .myignore
```

и добавьте `.myignore` в `.gitignore` обычным способом.

## Формат выходного файла

Каждый исходный файл оборачивается в маркеры:

```
===== FILE: <относительный/путь> =====
<содержимое>
===== END FILE =====
```

Это удобно для передачи в ИИ: модель видит границы файлов и их пути.
Относительные пути вычисляются от корня `source`.

Файлы, которые не удалось прочитать, попадают в вывод как:

```
===== FILE: <путь> (ОШИБКА ЧТЕНИЯ: <причина>) =====
```

## Пропуск бинарных файлов

По умолчанию утилита **не включает** бинарные файлы. Признаки:

1. Расширение входит во встроенный набор: изображения, архивы,
   аудио/видео, шрифты, `.exe`, `.dll`, `.so`, `.pyc`, `.class`,
   `.db`, `.sqlite`, `.jar` и другие (см. `DEFAULT_BINARY_EXT` в коде).
2. В первых 4 КБ содержимого встречается байт `\x00`.
3. Файл не открывается на чтение.

Чтобы включить всё содержимое подряд (в том числе бинарники):

```bash
python3 merge_files.py ./my_project bundle.txt --include-binary
```

## Разбиение по размеру

Флаг `--max-size N` (где N — число мегабайт, допускаются дробные
значения, например `0.5`) заставляет утилиту создавать несколько
файлов вместо одного.

- Имя частей: `<stem>_part<NNN><suffix>` (например, `bundle_part001.txt`).
- Нумерация трёхзначная (`001`, `002`, ...).
- Части создаются в той же директории, что и `output`.
- **Файл никогда не разрезается** между частями: если очередной файл
  не влезает в текущий лимит, начинается новая часть, а файл пишется
  целиком.
- Если один файл сам по себе больше `--max-size`, он всё равно будет
  записан целиком в отдельную часть.
- В режиме `--split-by-dir` нумерация частей **своя для каждой папки**.

## Разбиение по папкам

Флаг `--split-by-dir` группирует найденные файлы по **первому
компоненту** относительного пути.

| Путь файла | Группа | Целевой бандл (при `output=bundle.txt`) |
|---|---|---|
| `README.md` | `""` (корень) | `bundle.txt` |
| `src/main.py` | `src` | `bundle_src.txt` |
| `docs/api/spec.md` | `docs` | `bundle_docs.txt` |
| `tests/unit/test_a.py` | `tests` | `bundle_tests.txt` |

### Правила формирования имён

| `output` | папка | результат |
|---|---|---|
| `bundle.txt` | `src` | `bundle_src.txt` |
| `bundle.txt` | `docs` | `bundle_docs.txt` |
| `context.md` | `src` | `context_src.md` |
| `bundle` (без расширения) | `src` | `bundle_src` |

- Имя папки — это **первый компонент** относительного пути файла.
  Файлы внутри `src/core/` и `src/ui/` попадают в один `bundle_src.txt`
  (рекурсивно, без дальнейшего дробления).
- Файлы, лежащие прямо в корне `source`, идут в сам `output` (без суффикса).
- Если файлов прямо в корне нет, корневой bundle **не создаётся** —
  не будет пустого файла.
- При совместном использовании с `--max-size` нумерация частей у каждой
  папки своя: `bundle_src_part001.txt`, `bundle_src_part002.txt`, ...

## Статистика по подпапкам

В конце работы утилита печатает **дерево каталогов** с размерами и
количеством файлов в каждом узле. Это позволяет сразу увидеть, какая
ветка занимает больше всего места — и что имеет смысл исключить через
`.gitignore` или передавать в ИИ по частям.

### Как строится дерево

- Узлы — каталоги относительно `source` (корень обозначается `.<корень>`
  или `./`).
- У каждого узла выводятся: имя, количество файлов **в этом узле и всех
  потомках**, суммарный размер и доля от общего объёма.
- Узлы сортируются **по убыванию размера**; при равенстве — по имени.
- Ветки, размер которых меньше `--stats-min-bytes`, **сворачиваются**
  в одну строку `... (ещё N ветвей, X КБ)` — чтобы не засорять вывод
  мелочью.
- Считается **чистый размер исходных файлов** на диске (через `stat()`),
  без учёта служебных маркеров `===== FILE: ... =====`.

### Параметры

| Флаг | По умолчанию | Значение |
|---|---|---|
| `--stats-depth N` | `3` | Максимальная глубина дерева. `0` — без ограничения |
| `--stats-min-bytes N` | `1024` (1 КБ) | Ветки меньше N байт сворачиваются в «…» |
| `--stats-all` | выкл. | Эквивалент `--stats-min-bytes 0`: показывать всё |
| `--no-stats` | выкл. | Полностью отключить вывод статистики |


### Совместимость

- Работает и без `--split-by-dir` (когда всё пишется в один файл), и с ним.
- В режиме `--split-by-dir` статистика собирается **по всему дереву
  сразу** в одно дерево — независимо от того, сколько бандлов создалось.
- Не конфликтует с `--no-ignore`, `--include-binary`, `--max-size`.

## Типичные сценарии

### Подготовка контекста для ИИ в один файл

```bash
python3 merge_files.py ./my_project context.txt --max-size 2
```

Получите `context_part001.txt`, `context_part002.txt`, ... — и грузите
их в чат по очереди. В конце увидите дерево — какая ветка дала основной
объём.

### Понять, что занимает место

```bash
python3 merge_files.py ./my_project /tmp/throwaway.txt --stats-depth 0
```

Смотрим полное дерево и решаем, что добавить в `.gitignore`
(например, `assets/` или `data/`), чтобы уменьшить bundle.

### Передать только исходники, сгруппированные по папкам

```bash
python3 merge_files.py ./my_project ctx.txt --split-by-dir --max-size 3
```

Получите по одному-два файла на каждую папку верхнего уровня — удобно
выбирать, что именно подгружать в чат.

### Скрыть от ИИ и от git секреты

`.gitignore`:

```gitignore
# обычные правила
node_modules/
dist/

# приватные — не попадают в bundle, но и не мешают git
#!# *.pem
#!# *.key
#!# secrets/
#!# .env.local
```

```bash
python3 merge_files.py ./my_project bundle.txt
# Правил из /path/project/.gitignore: 2 обычных, 4 приватных
```

Ключи и секреты не попадут в bundle, а `git status` останется чистым.

### Только нужные расширения

Создайте `.myignore`:

```gitignore
*
!*.py
!*.md
!*.txt
!*.toml
!*.cfg
!*.ini
!*.json
```

Запуск:

```bash
python3 merge_files.py ./my_project src.txt --ignore .myignore
```

Здесь `*` игнорирует всё, а `!`-правила возвращают нужные расширения.

## Ограничения

- Не поддерживаются `.git/info/exclude` и глобальные `core.excludesFile`
  из git — только указанный файл игнорирования.
- Не поддерживаются вложенные `.gitignore` внутри подкаталогов: правила
  читаются из одного файла.
- `.gitignore`-паттерны с `**` в середине (например, `a/**/b/c`) работают,
  но редкие крайние случаи могут отличаться от поведения git.
- Содержимое читается как UTF-8 с заменой некорректных байтов
  (`errors="replace"`), поэтому даже «полу-текстовые» файлы не ломают вывод.
- `--split-by-dir` группирует только по **первому** уровню вложенности.
- В дереве статистики **нет отдельных листьев-файлов** — только каталоги.
  Увидеть размер конкретного файла можно через `--stats-depth 0`, но
  и там будут только каталоги; для пофайловой разбивки используйте
  `du -ah` или `ncdu`.
- Приватные правила `#!#` видны, если открыть `.gitignore` глазами; они
  не являются «секретными» для git — это лишь способ не менять поведение
  git. Для действительно локальных правил используйте отдельный файл
  (`--ignore .myignore` + `.myignore` в `.gitignore`).
